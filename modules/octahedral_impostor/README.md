# Octahedral Impostors — импостеры и билборды в редакторе (модуль `octahedral_impostor`)

Встроенный инструмент для создания октаэдрических импостеров: объект любой сложности
(дерево, камень, здание, группа мешей) запекается в атлас видов с разных направлений и
рисуется издалека одним квадом, который выглядит как исходный объект — с поворотом,
параллаксом, освещением и тенями. Основан на идеях
[Godot-Octahedral-Impostors](https://github.com/wojtekpil/Godot-Octahedral-Impostors)
(ShaderBits, IMP), но реализован нативно на C++ и встроен в логику редактора.

Тот же инструмент запекает и обычные **билборды**: один вид объекта на кваде, который
поворачивается к камере (или несколько скрещённых плоскостей), со стандартным
`StandardMaterial3D` — см. раздел [Билборды](#билборды).

## Классы

| Класс | Назначение |
|---|---|
| `OctahedralImpostorMaterial3D` (Material) | Материал импостера: квад поворачивается к камере, смешивает три ближайших вида, параллакс по глубине, объектные нормали, запись глубины поверхности, тени. Настраивается в инспекторе, конвертируется в `ShaderMaterial`. |
| `OctahedralImpostorBaker` (RefCounted, только редактор) | Запекание атласов импостера или текстур билборда (`type`) и сохранение результата; доступен и из редакторных скриптов (пакетное запекание). |

## Как пользоваться

1. ПКМ по узлу `Node3D` с мешами в доке **Сцена** (можно выделить несколько узлов)
   или по файлу сцены (`.tscn`, `.glb`, ...) в доке **Файловая система** →
   **Create Octahedral Impostor...** (или **Create Billboard...** — тот же диалог с типом
   *Billboard*, см. [Билборды](#билборды)).
2. В диалоге:
   - **Type** — *Octahedral Impostor* или *Billboard*.
   - **Layout** — *Hemisphere* (виды только сверху: деревья, камни, здания — больше
     разрешения для боковых видов) или *Full Sphere* (объект виден и снизу).
   - **Frames** — число видов на сторону атласа (12–16 обычно достаточно).
   - **Atlas Size**, **Supersampling** (сглаживание краёв), **ORM Atlas** (AO,
     roughness, metallic; без него используются средние значения материалов).
   - Строка с размером кадра, итоговым размером атласа и объёмом видеопамяти.
   - **Add to Scene as Level of Detail** + **Distance** + **Fade**: импостер добавляется
     дочерним узлом и показывается с заданного расстояния, а исходные меши скрываются
     там же (штатные *visibility ranges* с дизерингом кросс-фейда). Расстояние по
     умолчанию подбирается так, чтобы кадр атласа выводился примерно в своём разрешении
     на экране 1080p.
   - Справа — живое превью результата (вращение мышью, зум колесом) и просмотр
     атласов: альбедо, нормали, глубина. Превью перепекается при изменении настроек.
3. **Bake** — запекание с прогрессом (можно отменить), сохранение и импорт текстур,
   добавление в сцену одним действием с undo/redo. Повторное запекание в тот же путь
   обновляет меш на месте — все сцены, где он используется, сразу видят новый импостер,
   а незапекаемые настройки материала (прозрачность, backlight и т.п.) сохраняются.

Результат для `oak_impostor.tres`:

- `oak_impostor.tres` — `QuadMesh` с `OctahedralImpostorMaterial3D` и custom AABB
  (подходит для `MeshInstance3D` и `MultiMeshInstance3D`);
- `oak_impostor_albedo.png` — цвет (sRGB) и покрытие;
- `oak_impostor_normal_depth.png` — нормаль в пространстве объекта (RGB) и глубина (A);
- `oak_impostor_orm.png` — опционально.

Текстуры импортируются как VRAM Compressed (high quality) с мипмапами; у альбедо
включено сохранение покрытия альфа-теста в мипмапах, нормали не импортируются как
normal map. Изменённые пользователем настройки импорта при повторном запекании
сохраняются.

Пакетное запекание скриптом:

```gdscript
var baker = OctahedralImpostorBaker.new()
baker.frames = 16
for tree in get_tree().get_nodes_in_group("trees"):
    if baker.bake(tree) == OK:
        baker.save("res://impostors/%s.tres" % tree.name.to_snake_case())
```

## Билборды

Тип **Billboard** в диалоге (или `baker.type = OctahedralImpostorBaker.TYPE_BILLBOARD`) —
обычный билборд вместо импостера: дешевле и меньше по памяти, для объектов далеко или
похожих со всех сторон. Результат — меш со стандартным `StandardMaterial3D`, который можно
дальше настраивать как любой материал (backlight для листвы, порог альфа-теста и т.п.).

- **Billboard** — вид билборда:
  - *Y-Billboard* — квад поворачивается к камере вокруг вертикальной оси (деревья);
  - *Facing Camera* — квад всегда смотрит на камеру, в том числе сверху и снизу; вращается
    вокруг начала координат узла, поэтому лучше подходит для объектов с центром в начале
    координат;
  - *Cross* — несколько неподвижных вертикальных плоскостей (**Planes**, 2–4), скрещённых на
    вертикальной оси объекта, у каждой — вид со своей стороны (кусты, трава).
- **Texture Size** — размер длинной стороны текстур; вторая сторона подбирается по форме
  объекта (высокое дерево — высокая узкая текстура), стороны кратны 4.
- Запекается вид спереди (со стороны `+Z`, «лицевая» сторона модели в Godot), кадр
  подогнан по вершинам объекта с отступом в пару пикселей.
- **Supersampling**, **ORM Texture**, **Add to Scene as Level of Detail**, пакетное
  запекание, превью (вращение мышью, альбедо и карта нормалей) — как у импостеров.
  Дистанция LOD по умолчанию — там, где объект занимает около 128 px на экране 1080p
  (или дальше, если иначе текстура выглядела бы размытой): плоский билборд должен
  включаться, когда объект уже мал на экране.

Результат для `oak_billboard.tres`:

- `oak_billboard.tres` — `QuadMesh` с размером и смещением (`center_offset`) по виду объекта
  и custom AABB, достаточным для любого поворота (для *Cross* — `ArrayMesh` со скрещёнными
  плоскостями); материал `StandardMaterial3D`: альфа-тест, без отсечения задних граней,
  режим билборда (`billboard_mode` + `billboard_keep_scale`, чтобы работал масштаб узла и
  инстансов `MultiMesh`), карта нормалей, ORM или средние roughness/metallic материалов;
- `oak_billboard_albedo.png` — цвет (sRGB) и покрытие;
- `oak_billboard_normal.png` — карта нормалей в касательном пространстве квада
  (импортируется как normal map);
- `oak_billboard_orm.png` — опционально.

Квад билборда поворачивается вокруг начала координат узла (так работает `billboard_mode` в
`BaseMaterial3D`), а вид смещён относительно него так же, как объект: у дерева со стволом в
начале координат ствол остаётся на месте при любом повороте. Повторное запекание обновляет
меш на месте и сохраняет настройки материала, как у импостеров. Уже запечённые билборды
помечаются метаданными меша и не попадают в повторное запекание узла.

```gdscript
var baker = OctahedralImpostorBaker.new()
baker.type = OctahedralImpostorBaker.TYPE_BILLBOARD
baker.billboard_mode = OctahedralImpostorBaker.BILLBOARD_FIXED_Y
baker.atlas_size = 512
if baker.bake($Oak) == OK:
    baker.save("res://billboards/oak_billboard.tres")
```

## Как устроено запекание

- **Сбор геометрии**: `MeshInstance3D`, `MultiMeshInstance3D`, корневые `CSGShape3D`
  с материалами поверхностей, override/overlay, blend shapes и instance-параметрами
  шейдеров. Пропускаются скрытые узлы, shadow-only геометрия, дальние LOD
  (`visibility_range_begin > 0`) и сами импостеры (повторное запекание не захватывает
  старый импостер).
- **Ограничивающая сфера** считается по вершинам (а не по AABB), с отступом в пару
  пикселей кадра — плотнее и больше разрешения на объект.
- **Рендер** — собственный сценарий RenderingServer без окружения и света, HDR-вьюпорт
  (без квантования и sRGB), без LOD мешей и occlusion culling. Все виды региона
  атласа рисуются за один проход: копии геометрии повёрнуты к ортографической камере.
  Рендер синхронный (`RS::draw` только для вьюпорта бейка, как у превью ресурсов),
  без ожидания кадров. Атлас рендерится регионами до 2048 px, что позволяет
  суперсэмплинг и большие атласы при ограниченной памяти (вид билборда, больший
  региона, рендерится по частям).
- **Проходы**:
  - альбедо — отладочный режим *Unshaded*: цвет настоящих материалов (любых, включая
    `ShaderMaterial`) с их прозрачностью;
  - нормали и глубина — в Forward+ читаются полноэкранным проходом из
    normal-roughness буфера и буфера глубины, поэтому учитываются normal maps и
    кастомные шейдеры любых материалов; в Mobile/Compatibility — через материалы-замены;
  - ORM — через материалы-замены, повторяющие параметры `BaseMaterial3D` (включая ORM
    текстуры и каналы) и распространённые имена параметров `ShaderMaterial`.
- **Постобработка** на CPU: даунсэмплинг с учётом покрытия, перевод нормалей в
  пространство объекта (у билбордов — в касательное пространство квада), заполнение
  пустых пикселей каждого вида цветами соседей (без протекания между видами), чтобы
  фильтрация и мипмапы не приносили фон.

## Шейдер импостера

- Квад строится вокруг ограничивающей сферы и поворачивается к камере (в
  ортографической проекции и в проходах теней — по направлению камеры/света).
- Смешивание трёх ближайших видов (барицентрические веса в ячейке сетки),
  UV каждого вида — пересечение луча взгляда с плоскостью кадра.
- Параллакс по глубине каждого вида.
- Нормали в пространстве объекта (корректно смешиваются между видами, работают в
  `MultiMesh`).
- **Depth offset**: фрагменты пишут глубину реальной поверхности и освещаются в её
  точке (`LIGHT_VERTEX`) — корректные пересечения с землёй, форма теней и отсутствие
  самозатенения; тени отбрасываются тем же мешем (`IN_SHADOW_PASS`), отдельный
  теневой меш не нужен.
- Мипмапы с ограничением уровня (кадр не меньше 8 px), alpha scissor / alpha hash /
  alpha to coverage, backlight для листвы, цвет вершин/инстансов `MultiMesh`.

## Отличия от аддона-основы

| Аддон (GDScript) | Модуль |
|---|---|
| Дублирование узлов сцены, ожидание кадров и сканирования файловой системы | Нативный рендер через RenderingServer, синхронный, без дублирования узлов |
| Один вьюпорт размером с атлас, без сглаживания | Регионы, суперсэмплинг, атласы до 8192 |
| Нормали из материалов-замен (только известные параметры) | Нормали из G-буфера Forward+ для любых материалов |
| Нормали в пространстве кадра | Нормали в пространстве объекта |
| Сфера по диагонали AABB | Сфера по вершинам |
| Отдельный теневой меш со смещением | Depth offset и тени в том же материале |
| Без мипмапов | Мипмапы с сохранением покрытия и ограничением уровня |
| LOD через узел со скриптом в `_physics_process` | Штатные visibility ranges с кросс-фейдом, undo/redo |
| PNG + ожидание импорта | Настройки импорта (VRAM, мипмапы) и синхронный реимпорт |

## Ограничения

- Масштаб узла с импостером должен быть равномерным.
- Прозрачные (alpha blend) материалы запекаются как альфа-тест; анимации, ветер и
  скелеты — в текущей позе. Материалы, зависящие от мировых координат (трипланар в
  мировом пространстве, шум по позиции), запекаются в позициях копий при бейке.
- Виды снизу в раскладке Hemisphere заменяются видами горизонта.
- Билборд показывает один вид (у *Cross* — по виду на плоскость, с обратной стороны —
  зеркальный): несимметричные объекты сбоку выглядят как вид спереди. *Y-Billboard* при
  взгляде строго сверху вырождается в линию (как любой `BILLBOARD_FIXED_Y`).
